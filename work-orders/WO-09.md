# WO-09 — Typed records and HTTP API

## Summary

Replace the superseded synthesis work order with the FastAPI backend specified
in AGENTS.md and the owner's November 14 implementation request. Preserve the
existing SQLite/JSONL store, add typed record validation and indexed projections,
then serve the documented `/api` shapes to WO-08's interface.

## Acceptance Criteria

- One canonical module defines Source, Run, Variant, EvalResult, HealAttempt,
  Critique, DataNeed and Event models with schema versions, described fields and
  enums for every status. Preserve all existing information during migration.
- Validate every existing business-table row and every `runs/events.jsonl`
  line; report each mismatch and its migration. Back up the original store;
  migrate atomically and verify record/field preservation. Unknown information
  stays unknown rather than receiving fabricated metrics or dates.
- Route every writer through those models. Add indexed columns or views for
  API filters/sorts: run_id, source_id, variant, status, created_at and voided.
  Voided records remain auditable and are excluded by default everywhere.
- Inventory existing logs and artifacts, mapping each to an API/UI surface:
  database, event stream, ingest history, audit results, per-symbol metadata,
  data contract, WO-17 evidence, graveyard and generated strategies. Report the
  models and inventory at the Phase 1 checkpoint before API implementation.
- Extend AGENTS.md's API contract before implementing any additional shape.
  Serve models through `factory/api/`, including runs, leaderboard, variant
  details, structured graveyard, data catalog/preview, artifacts and eval schema.
- Per-variant ordered steps cover code generation, healing when present,
  Evals 1–5 and critic; states, detail lines and logs are derived from persisted
  evals, heal attempts and events. Do not invent progress or estimated completion.
- Deterministic templates generate one-sentence variant summaries. No LLM call
  creates or changes authoritative status, metric or verdict text.
- Dataset previews provide downsampled bars, split boundaries, coverage and
  gaps; ingest history comes from `data/ingest.jsonl`, audit fill statistics from
  `data/audit.json`, and field descriptions from the canonical contract.
- The read-only eval schema uses the actual values in `factory/evals/config.py`
  with names, plain-English questions, checks and thresholds. Eval logic and
  configuration remain unchanged.
- SSE replays from sequence zero, supports reconnects, and follows a new live
  run. PDF submission returns a durable run identifier before background work.
- Endpoint tests validate documented shapes using the real local records and
  isolated migration/test copies, including failed extraction, inactive and
  void records. Never weaken the model or omit a failing row to pass a test.
- Secrets never enter API responses or served artifacts. Artifact identifiers
  resolve through an explicit inventory, not arbitrary filesystem paths.

Phase 1 and Phase 2 acceptance completed on November 14: typed migration report
in [docs/RECORDS.md](../docs/RECORDS.md), full artifact mapping in
[docs/RECORD_INVENTORY.md](../docs/RECORD_INVENTORY.md), and API verification in
[docs/API.md](../docs/API.md). Full suite: 375 passed; 84 additional requests
checked the actual retained records. The real browser-submitted run remains
Phase 4's acceptance check.

## Out of Scope

No store replacement, strategy synthesis, HOLDOUT strategy runs, changes to
strategy contracts or eval logic/configuration, fake model/provider outputs,
new data downloads, trading, auth, multi-user deployment or unimplemented
future controls. WO-10–WO-14 and editable WO-16 profiles remain unavailable.
