**Timestamp meaning and availability**

| Tier | Actual index meaning | Stored zone/type | Available-price interpretation |
|---|---|---|---|
| 1min | Start of the one-minute interval, left-inclusive/right-exclusive | UTC `datetime64[ns, UTC]` | A 09:59 New York bar contains trades before 10:00; its close is not known at 09:59. Normal-session last label is 15:59, not 16:00. |
| 1day (including smoke) | The trading date at **midnight America/New_York**, converted to UTC; a day-bucket/session label, not the session open or close | UTC `datetime64[ns, UTC]`, 04:00Z in daylight time / 05:00Z in standard time | The daily values are not known at the index timestamp. The repo stores neither an availability timestamp nor the final provider revision time. |

Evidence: `factory/data.py:62–73`, `factory/ingest_alpaca.py:113–162`, actual
`data/1min/SPY.parquet` and `data/1day/SPY.parquet`. The writer preserves
provider labels; it does not relabel minutes to their ends.
[Alpaca's aggregation FAQ](https://docs.alpaca.markets/us/docs/market-data-faq)
confirms start labels and New York day buckets.

The engine uses `target.shift(1)` and close-to-close returns
(`factory/engine.py:99–112`). A decision using a minute bar's close belongs at
that bar's end, and the target earns the next bar's close-to-close return. The
engine does not automatically close positions at session boundaries. These
conventions must be explicit in the generated contract and canary.

Minute grids include the exchange open and exclude the close. Daily grids use
session dates. All symbols share this calendar; individual listing exchanges

**Exact stored columns, dtypes and units**

All 560 Parquet files have the same Arrow schema and the same pandas dtypes;
there are no schema variations among the three groups. Arrow fields are declared
nullable, but the full scan found no null values.

| Physical Parquet field | Arrow dtype | pandas representation | Unit / meaning |
|---|---|---|---|
| `open` | double | float64 column | USD per share, adjusted first eligible price |
| `high` | double | float64 column | USD per share, adjusted highest eligible price |
| `low` | double | float64 column | USD per share, adjusted lowest eligible price |
| `close` | double | float64 column | USD per share, adjusted last eligible price |
| `volume` | double | float64 column | Provider-reported shares, split-adjusted; not dollars or trade count |
| `is_filled` | bool | bool column | True only when this repository synthesized the bar |
| `timestamp` | timestamp[ns, tz=UTC] | named DatetimeIndex, not a pandas data column | UTC instant representing the tier-specific label above |

All observed volumes happen to be integer-valued floats. There is no integer
volume invariant today. Currency is the provider's default USD, not a field or
checked local invariant. Symbol comes from the filename and metadata; frequency
comes from the directory/metadata. There are no `trade_count`, `vwap`,
`available_at`, adjustment factors, session columns or per-row source fields.
The provider's `n` and `vw` fields are discarded by the writer's OHLCV selection.

`data/sp500.csv` is the only stored CSV dataset. Its exact columns are
`symbol`, `name`, `GICS Sector`, `GICS Sub-Industry`, `Headquarters Location`,
`Date added`, `CIK`, and `Founded`. `read_universe(dtype=str)` loads all eight as
pandas `object` string columns. They have no physical units: symbol/name/classification/
location are labels; CIK is an identifier; Date added is date text; Founded is
unparsed text rather than an enforced year/date type. It has 503 rows. Snapshot
source and retrieval time are in `data/sp500.source.json`.

Auxiliary files are provenance/operational records, not event-signal datasets:
- Each `data[/smoke]/metadata/<tier>/<symbol>.json` contains string fields
  `symbol`, `frequency`, `start`, `through`, `feed`, `adjustment`, `request_id`,
  `first_timestamp`, `last_timestamp`, `written_at`; integer fields
  `normalizer_version`, `source_rows`, `off_session_rows`, `expected_rows`,
  `observed_rows`, `filled_rows`, `missing_rows`, `rows`; and float `fill_rate`.
  Counts are bars; fill_rate is a fraction of the expected grid, not a percent
  or fraction of stored rows. Start/through are dates; timestamp fields are UTC
  ISO strings. Request ID is a request-configuration hash, not a data checksum.
- Tier manifests contain `frequency`, `symbols`, `start`, `through`, `feed`,
  `adjustment`, `normalizer_version`, `splits`, `complete`, `failed_symbols`.
  Frequency/start/through/feed/adjustment are strings; normalizer_version is an
  integer; symbols/failed_symbols are string arrays; complete is boolean; splits
  map IS/OOS/HOLDOUT to inclusive UTC start/end strings. There is no schema version,
  per-dataset source URL, currency, calendar version or dataset checksum.
- `sp500.source.json` stores source URL, retrieved_at, integer symbol count and
  a limitation string. `ingest.jsonl` stores typed `chunk_written`,
  `symbol_complete` and `wide_load_benchmark` records with UTC `time` strings.
  Benchmark seconds are floats and memory bytes are integer byte counts.
- `audit.json`, `audit.txt` and `wo02-smoke.json` are prior audit/plumbing results;
  `.ingest.lock` files are empty coordination files. They are not strategy inputs.

**Adjustment evidence and its limits**

Both production tiers and the smoke tier request and record `feed=sip`,
`adjustment=all`, `normalizer_version=1`. Local code performs no further price
or volume adjustment. Per-symbol metadata agrees with the manifests throughout.

According to the [Alpaca adjustment reference](https://docs.alpaca.markets/us/reference/stockbarsingle-1),
`all` covers splits, cash dividends and spin-offs. Splits adjust price **and
volume**; dividends and spin-offs adjust price. Thus volume uses split-adjusted
share units; it is not rescaled by the full dividend-adjusted price factor.

Stored NVDA evidence around the June 2024 split is consistent with adjusted
prices: minute June 7 close 120.52 → June 10 open 120.01 (ratio 0.995768);
daily 120.54 → 120.03 (0.995769). These values are also in `data/audit.json`.
This checks a price discontinuity only. **No raw response, unadjusted history or
corporate-action factor ledger is retained, so this audit cannot independently
prove every price/volume adjustment factor.** Provider provenance is the present
basis for the volume claim. No redownload was performed to fill that evidence gap.

**Gap filling and recoverability**

The only shared price-data fill is `clean_bars()` (`factory/data.py:110–123`):
reindex to the XNYS grid, then within each New York session forward-fill the last
observed close for at most five consecutive missing minutes. OHLC are all set
to that close, volume to zero, and `is_filled=True`. Leading session gaps and
minutes beyond the fifth missing minute remain absent. Filling never crosses a
session, holiday or overnight boundary. Daily bars are never locally filled.

Reconstructing this rule from stored non-filled rows reproduced every minute
fill mask and every synthetic close exactly. Aggregate minute fill count is
**39,230 / 14,620,500 expected bars = 0.268322%**. Largest counts: FDX 13,488
(4.6127%), COST 8,322 (2.8460%), GS 4,722 (1.6149%), LOW 3,115 (1.0653%).
For example, LOW at `2023-11-15T14:31:00Z` has OHLC 190.57, volume 0,
`is_filled=True`.

Remaining minute gaps: COST 1; CVX 5; DIS 2; FDX 19; GS 1; HD 1; LOW 199;
MA 1; MRK 43; MS 43; PG 18; TGT 22; UNH 3; UPS 91; XOM 3. Total **452**.
Daily files have **50,876 absent expected symbol-sessions**, all before each
symbol's first retained row, with zero interior calendar gaps. This is consistent
with unequal listing/history coverage but does not prove a listing date; no
instrument-lifetime metadata is present.

The fill flag is lost in three places: `load_bars()` requests only OHLCV
(`data.py:182`), `normalize_bars()` selects only OHLCV (`data.py:81`), and the
sandbox stages only OHLCV (`sandbox.py:64`). Workers cannot distinguish a filled
bar from an observed bar after loading. `wide_frames()` likewise returns five
OHLCV matrices and leaves alignment gaps as NaN, without filling them.

The engine does not fill prices: `pct_change(fill_method=None)` leaves missing
returns undefined and raises when exposure is nonzero. It replaces undefined
returns with zero only after confirming exposure is zero. This is accounting
for a flat position, not fabrication of a market bar. Generated strategy code
can call ffill/bfill/fillna for its own computations; those calls do not rewrite
the stored datasets and are subject to lookahead tests.

**Inconsistencies and unresolved semantics**

1. **Daily volume is not regular-session minute volume.** The cleaner removes
   off-session minute rows but keeps the provider's whole daily aggregate. For
   SPY on 2024-03-11, summed stored minute volume is 51,316,092 shares while the
   daily value is 62,557,183; the last minute close is 495.04 while daily close
   is 495.06. On the 2024-11-29 half day, volumes are 20,793,986 versus 30,177,351
   and closes 588.83 versus 588.93. Provider daily/minute trade-condition rules
   differ, including extended-hours volume and closing-price treatment; a daily
   bar is not a simple reduction of this RTH-only minute tier. The existing
   hand-written prompt's blanket claim that daily OHLCV is available after the
   session closes does not establish when final daily volume was knowable.
2. **926 flat zero-volume daily bars are marked observed, not filled.** Counts:
   BIIB 2; DOW 396; DXCM 1; EXE 156; SMCI 349; VRT 22. Example: DOW
   `2017-09-01T04:00:00Z`, all prices 44.18, volume 0, is_filled=False. Current
   daily cleaning never fills; these are classified as source rows. Without raw
   responses, their upstream origin cannot be verified. Do not equate
   is_filled=False with proof that trading occurred, or infer synthetic status
   from zero volume alone.
3. **Enforcement is incomplete despite structurally consistent files.** Every
   actual file passed finite/positive OHLC, OHLC ordering, nonnegative volume,
   unique/order/UTC/calendar checks, fill reconstruction and metadata checks.
   But isolated loader probes accepted a minute at 14:30:01, a Saturday bar,
   and a file lacking is_filled. A negative-volume row was rejected with only
   `Source volume must be nonnegative`, without dataset/rule/row context.
   The loader ignores per-symbol metadata, schema version, adjustment and feed
   validity; normalization sorts/coerces/deduplicates instead of strict checking.
   `atomic_parquet()` itself has no validation, and ingestion resume trusts
   request_id without revalidating existing data. The old audit mostly checks
   row counts/metadata plus one split example, not all row invariants.
4. **Session/fill semantics disappear before execution.** Neither strategies
   nor prompts receive generated session fields. The prompt contains manually
   maintained timing prose, while AGENTS.md and worker CONTRACT separately
   describe OHLCV. No canonical contract or freshness test connects them.
5. **Splits are tier-specific bar counts and can cut a session.** Minute IS
   ends `2025-09-04T14:35:00Z`, OOS starts 14:36; OOS ends
   `2026-04-13T13:47:00Z`, HOLDOUT starts 13:48. Daily boundaries are different:
   IS ends 2022-07-07, OOS ends 2024-09-09. They are not common calendar periods
   across tiers. The current engine starts each evaluation slice flat.
6. **Provenance is incomplete.** There is a normalizer version and written_at,
   but no schema_version, explicit provider source URL, currency/calendar/asof
   identity, dataset checksum or retained raw/factor source. Symbol history
   mapping uses the provider default `asof`, which is not recorded. All current
   stored metadata matches; the problem is missing semantics/enforcement, not an
   observed metadata mismatch. The S&P universe is current membership and has
   the already-documented survivorship limitation.
7. **Activity is informational only today.** The recorder counts active bars
   after evals; it does not count traded days or raise INACTIVE before Eval 2.
   The prior all-inactive run remains COMPLETED with failed variant verdicts;
   it has not yet been voided. There is no product leaderboard API yet, and
   current DSR accounting is scoped to siblings in a run, not all past DB rows.
   Static tracing of its stored strategies in
   `strategies/p_9eb3b8cfaadaf4ea/r_449ef7fd3ae6/` confirms the timing failure:
   A (lines 51–60) and C (lines 83–102) require a 16:00 label to obtain a
   previous-session close, but that label is absent from this minute tier.
   B (lines 51–56) additionally computes minutes per hour as
   `(960 - 930) / (960 / 600 - 1)`, approximately 50 instead of 60; its
   resulting clock never reaches the required 930/960 entry/close endpoints.
   No strategy was executed or repaired as part of this audit.
8. **Step 5 prerequisite:** `papers/zarattini_aziz_barbon_beat_market.pdf` is
   absent. No replacement paper was downloaded or substituted in this audit.
