# WO-06 Workers and self-heal

## Summary

Three model proposals execute concurrently. Validation and at most three bug
repairs use IS only. Repair-provider errors now close the attempted repair record,
retain prior repair usage, and cannot poison sibling Eval 5 accounting.

## Acceptance Criteria

Real `gpt-6.1-sol` A/B/C proposals were generated for the Gao paper in
`r_449ef7fd3ae6`; see WO-07. No repairs were triggered in that live run.

Offline regression tests execute an injected lookahead bug in the real sandbox
and Eval 1, then fix it with one mocked repair response. Both SQLite and JSONL
record the failed validation and successful repair. Additional tests verify
parallel generation, the three-repair cap, and a provider failure after an
already-billed repair. These fixture tests are not evidence of a live model
repair; the real run did not exercise that path.

The real run exposed a context omission: generated intraday code assumed
end-labelled bars including 16:00, while local bars are start-labelled and end
at 15:59. Worker schema prompts now state minute/daily timestamp conventions
and the engine's close-to-close lag. Original generated variants and failed
verdicts are preserved; no metric-driven regeneration was performed.

## Out of Scope

Workers receive no OOS or HOLDOUT observations. Failed metrics never trigger
repair. No eval threshold, source policy or sandbox restriction was weakened.
